# Improve resident AI and tools

The default demo is a deterministic fictional world. It does not use a provider key, call a model, activate a budget or execute generated programs. Generic AI source is included so contributions can improve the same prompt, typed decision, tool, testing and revision interfaces used by the private project. Private production composition and personal inputs are excluded.

## Included interfaces

- `apps/world-service/src/openai-resident-provider.ts`: `OpenAIResidentProvider({apiKey, model})` requires both values explicitly. Its transport uses the fixed Responses endpoint. `decidePublic` accepts a strict `PublicResidentContext`, validates an offered token and typed design, and accepts an AbortSignal. The source also retains the local provider and bounded prompt composer. No model, key or personal context is selected for you.
- `resident-workbench/transport.ts`: `ResponsesWorkbenchTransport({apiKey, model}, request, preflight)` makes bounded tool requests. `CountingPreflight(request)` is available from token-preflight.ts. These libraries do not establish a monetary ceiling; configure your own provider account limits and explicit request authority before use. Merely importing them makes no network call.
- `resident-workbench/session.ts`: `WorkbenchSession(WorkbenchStore.open(ownedPath, syntheticContext), trustedFixtures, executor)` supports submit_module, test_module, propose_method. `session.run(transport, signal)` bounds requests and revisions. Fixtures, numeric context and the output directory are explicit trusted host inputs. Do not supply personal continuity, letters, real-world journals or a saved production world.
- Artifacts and failed versions are real locally persisted test evidence. The session re-executes each case, validates deterministic output, grades materials/quality/time and permits only a tested passing proposal. It does not award canonical materials, construction or knowledge. Reopening a journal is inert; private canonical admission is deliberately unavailable in this public core.

## Execution profiles and current limits

`DockerWorkbenchExecutor` is the existing explicit Linux arm64 / Node v24.18.1 adapter. It requires a separately reviewed immutable runtime record, has no image discovery/build/pull and uses network-none, read-only, unprivileged bounded containers. Its runner is included; no runtime binary, ready record or implicit Docker activation is included. This is not a portable amd64 setup command or a claim of native acceptance on your machine.

The private production composition uses a different existing Linux amd64 socket adapter (`socket-executor.ts`), requiring a protected root-owned manifest, an exact admitted runtime and an authenticated execution broker. Its client source is included for review and interface contributions. The privileged broker, active manifest, source proof, writer/cgroup identities and production enablement are excluded. The arm64 adapter's constraints do not mean the private project's amd64 route is absent. Neither profile is enabled by the demo.

You can exercise request construction and tool/revision behavior with the included offline tests. To exercise real AI, supply your own key/model to the above provider/transport explicitly in your own local caller, use a finite AbortSignal and a separately approved executor. The optional offline host binder has tested failure/repair through canonical admission, verified cold restart and a typed adopt-version kernel transition with configured doubles. There is no bundled live launcher or production canonical adoption path; provider/native execution, paid useful work and teaching remain unproved. Native runtime qualification, your spending policy and any desired public canonical method integration remain explicit next work, not implied by passing offline tests.

Contributions should improve prompt relevance, legal choices, closed failures, revision feedback and measured usefulness. Do not add private chain-of-thought, raw provider prompts, personal files or credentials to the public activity panel. That panel reports admitted tasks and changes; request-stage telemetry remains a separate missing capability.
